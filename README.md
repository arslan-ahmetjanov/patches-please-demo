# Patches, Please: демо-репозиторий

Учебный сервис «Заметки» с намеренно внедрёнными уязвимостями. Это объект
проверки системы автоматизированного контроля безопасности разработки
[Patches, Please](https://github.com/arslan-ahmetjanov/patches-please): на нём
видно, как три сканера находят проблемы, политика выносит вердикт `fail`, а
baseline переводит тот же набор находок в `pass`.

**Не разворачивайте сервис и не используйте его код в работе.** Ошибки внедрены
специально, все имена, адреса и значения вымышлены.

## Что внутри

| Файл | Что показывает |
| --- | --- |
| `app.py` | Небезопасные вызовы для Semgrep и фиктивный секрет для Gitleaks |
| `requirements.txt` | Устаревшие зависимости с известными уязвимостями для Trivy |

В `app.py` намеренные `eval`, `subprocess` с `shell=True` и `pickle.loads`;
рядом есть безопасная функция `export_note` для контраста. Константа
`API_TOKEN` это заглушка вида `pp_…`, она нигде не зарегистрирована и доступа
не даёт.

## Стек

| Слой | Технологии |
| --- | --- |
| Язык | Python 3 |
| SAST | Semgrep, локальный набор правил `patches-please.python` |
| Секреты | Gitleaks, правило `generic-api-key` |
| Зависимости | Trivy по манифесту `requirements.txt`, офлайн-база в образе |
| Платформа проверки | Patches, Please: прогон, нормализация, политика, baseline |

## Ожидаемые находки

| Сканер | Тип | Находка | Уровень в отчёте |
| --- | --- | --- | --- |
| Semgrep | SAST | `eval` в `app.py` | medium |
| Semgrep | SAST | `subprocess` с `shell=True` в `app.py` | medium |
| Semgrep | SAST | `pickle.loads` в `app.py` | medium |
| Gitleaks | секреты | `generic-api-key` в `app.py` | medium |
| Trivy | зависимости | уязвимости в `requests`, `PyYAML`, `Jinja2` | high и medium |

На проверке 27.11.2026 прогон дал 15 находок: 3 SAST, 1 секрет и 11
зависимостей (высокие: CVE-2020-14343 в PyYAML 5.3.1 и CVE-2019-10906 в
Jinja2 2.10, остальные `medium`). Точное число находок Trivy зависит от базы
уязвимостей, зашитой в образ при сборке, и может меняться: важно, что
присутствуют все три класса. Сообщение находки-секрета в отчёте заменено
заглушкой `[секрет скрыт]`.

## Как проверить

1. Заведите проект в Patches, Please с адресом этого репозитория и веткой
   `main` (публичный адрес обязателен: worker клонирует его без учётных данных).
2. Запустите прогон на коммите ветки `main`:

```bash
uv run patches-please scan \
  --provider github \
  --commit <полный SHA> \
  --ref main \
  --wait
```

3. Первый прогон завершается кодом `1` и вердиктом `fail`: находки `high` новые
   и не покрыты baseline. Это ожидаемое поведение, а не ошибка настройки.
4. Поставьте baseline по этому прогону и запустите проверку на новом коммите,
   не меняющем `app.py`, например с правкой этого README. Второй прогон
   завершается кодом `0` и вердиктом `pass`: те же находки получают состояние
   `existing`.

## Почему это безопасно

- Секрет это заглушка, сгенерированная для проверки. Она нигде не зарегистрирована
  и не даёт доступа ни к одному сервису.
- Зависимости не устанавливаются: файл нужен только Trivy, который читает
  манифест и не запускает код.
- Уязвимые вызовы не выполняются: приложение никто не запускает.
- В отчётах прогона значение секрета замаскировано.

## Известные ограничения

- Число находок Trivy зависит от базы в образе worker: после пересборки образа
  оно может измениться.
- Набор правил Semgrep минимальный: три правила. Реестр `p/...` в офлайне
  недоступен.
- Gitleaks сканирует рабочее дерево клона, а не историю git: проверяется
  текущий коммит.
- Baseline ставится скриптом заполнения стенда, отдельного метода REST API нет.
- Уровни Semgrep и Gitleaks в отчёте `medium`: их SARIF не заполняет `level`
  результата, и нормализатор применяет умолчание.
