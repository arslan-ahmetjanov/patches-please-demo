# Демо-репозиторий Patches, Please

Учебный сервис «Заметки» с намеренно внедрёнными уязвимостями. Это объект
проверки для системы Patches, Please (CON-003): на нём показывают, что три
сканера находят проблемы, политика выносит вердикт, а baseline и исключения
меняют результат.

Репозиторий публичный и существует только для демонстрации. Не разворачивайте
сервис и не используйте его код в работе: ошибки внедрены специально.

## Что внутри

| Файл | Что показывает |
| --- | --- |
| `app.py` | Небезопасные вызовы для Semgrep и фиктивный секрет для Gitleaks |
| `requirements.txt` | Устаревшие зависимости с известными уязвимостями для Trivy |

Все имена, адреса и значения вымышлены. Настоящих ключей, токенов и данных
организаций в репозитории нет.

## Ожидаемые находки

| Сканер | Тип | Что найдёт |
| --- | --- | --- |
| Semgrep | SAST | `eval`, `subprocess` с `shell=True`, `pickle.loads` |
| Gitleaks | секреты | фиктивный токен в `app.py` |
| Trivy | зависимости | уязвимости в версиях из `requirements.txt` |

Точные правила и уровни важности зависят от версий сканеров и базы уязвимостей,
зашитых в образ worker. Актуальный список — в отчёте прогона.

## Почему это безопасно

- Секрет — заглушка вида `pp_…`, сгенерированная для проверки. Она нигде не
  зарегистрирована и не даёт доступа ни к одному сервису.
- Зависимости не устанавливаются: файл нужен только Trivy, который читает
  манифест и не запускает код.
- Уязвимые вызовы не выполняются: приложение никто не запускает.

## Как использовать

1. Опубликуйте содержимое этого каталога отдельным публичным репозиторием —
   инструкция в `docs/demo.md` основного проекта.
2. Заведите проект в Patches, Please с адресом этого репозитория.
3. Запустите прогон на коммите ветки `main`.
4. Сравните результат с таблицей выше и сценариями S-001…S-003 в спецификации.
